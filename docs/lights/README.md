# Руководства BetterLights для BBS Animation Editor

**Совместимость:** Minecraft 1.12.2, Blockbuster 2.7.1, BetterLights 1.0.3.PREVIEW, Java 8.

Раздел LIGHT теперь использует **один нативный источник данных** — `BetterLightsMorph.getValueManager()` / `ValueSerializer`. Настройки не копируются в собственную параллельную структуру: всё сохраняется в NBT морфа, через существующий редактор сцены.

## Четыре отдельных руководства

1. [LIGHT — обычный свет, цвет, интенсивность, дальность и конус](01-light.md)
2. [SHADOWS — тени, дальность, FOV и угловые параметры](02-shadows.md)
3. [FLARE EFFECT — блики, цвет и палитра](03-flare.md)
4. [VOLUMETRIC FOG EFFECT — объёмный луч, плотность и качество](04-volumetric-fog.md)

## Где их найти в редакторе

- **CAMERA → LIGHTS → выбрать источник → LIGHT:** четыре вкладки `LIGHT | SHADOWS | FLARE | FOG`. Статичный свет не использует ключи.
- **POSE → актёр с BetterLightsMorph → LIGHT:** те же четыре группы. Если выбран Origin-ключ, параметры можно сохранить на ключе; иначе меняются базовые параметры актёра.
- **ORIGIN / TARGET:** независимые мировые точки; одинаковый 3D-гизмо. Они заменяют нативные Position/DirectionXYZ, чтобы не создавать конкурирующие способы перемещения.

## Элементы управления

| Контрол | Действие |
|---|---|
| Четыре вкладки | Каждая показывает только параметры своей группы; список скроллится отдельно. |
| Переключатель | Нажатие мгновенно меняет нативное логическое свойство. |
| Ползунок | ЛКМ или перетаскивание с ограничением по минимальному и максимальному значению именно установленной версии BetterLights. |
| Числовое поле | ЛКМ по числу, точное значение, Enter для подтверждения, Esc для отмены. |
| Цветной образец | Открывает палитру H/S/V + ползунок альфа. |
| Поле `#AARRGGBB` | Введите точный цвет в шестнадцатеричной форме. |
| Колесо мыши | Переключает видимые строки в пределах выбранного раздела. |

## Важные различия

- Выключение **статичного источника** в CAMERA и переключение `LIGHT.Enabled` не обязательно одно и то же. Первое удаляет источник из списка активных на время рендера, второе меняет параметр внутри самого BetterLights.
- Эффект теней не появится без поддержки нужного шейдерного/BetterLights-пути.
- Блик и видимая дымка — отдельные эффекты, не просто увеличение яркости света.
- **DirectionX/Y/Z скрыты в интерфейсе редактора**, поскольку результирующее направление уже вычисляется из Origin/Target. Исходные значения сохраняются в NBT.
- Если конкретная сборка BetterLights добавляет ещё одно нативное числовое/цветовое/логическое поле, оно автоматически появляется в соответствующей группе (определяется префиксом `Shadows.`, `Flare Effect.`, `Volumetric Fog Effect.`).

## Ограничение по точности документации

На приложенных исходных скриншотах видны только части некоторых вложенных разделов, особенно **Flare Effect** и часть **Shadows**. Значения, имена и диапазоны неразличимых полей не придуманы; их можно подтвердить по установленному BetterLights 1.0.3 и дополнить эту документацию после теста. Не следует путать универсальные принципы работы освещения с точно подтверждёнными подробностями реализации конкретного шейдера.

Для инженерных подробностей об Origin/Target, сохранении света и порядке рендера: [BetterLights CAMERA guide](../betterlights-camera-guide.md).
